# 贡献指南

感谢您对HotKey Go Client项目的关注！我们欢迎各种形式的贡献，包括但不限于代码、文档、测试、问题报告等。

## 🚀 快速开始

### 环境要求

- Go 1.19 或更高版本
- Git
- 基本的Go开发环境

### 设置开发环境

1. **Fork项目**
   ```bash
   # 在GitHub上fork项目到您的账户
   ```

2. **克隆代码**
   ```bash
   git clone https://github.com/YOUR_USERNAME/hotkey.git
   cd hotkey/client_go
   ```

3. **安装依赖**
   ```bash
   go mod download
   ```

4. **运行测试**
   ```bash
   go test -v .
   go test -v ./startup
   ```

5. **运行示例**
   ```bash
   go run examples/quick_start.go
   ```

## 🔧 开发规范

### 代码风格

1. **Go规范**: 遵循官方Go代码规范
2. **格式化**: 使用 `go fmt` 格式化代码
3. **Lint检查**: 使用 `golint` 和 `go vet` 检查代码
4. **命名规范**: 使用清晰、有意义的变量和函数名

### 提交规范

使用约定式提交格式：

```
<类型>[可选的作用域]: <描述>

[可选的正文]

[可选的脚注]
```

**类型：**
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `style`: 代码格式（不影响功能）
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建过程或辅助工具的变动

**示例：**
```
feat(startup): add event-driven startup management

Add EventDrivenStartup for detailed phase tracking and event subscription.
Includes startup phases, event publishing, and subscriber management.

Closes #123
```

### 分支策略

1. **主分支**: `main` - 稳定版本
2. **开发分支**: `develop` - 开发版本
3. **功能分支**: `feature/功能名` - 新功能开发
4. **修复分支**: `fix/问题描述` - Bug修复
5. **发布分支**: `release/版本号` - 发布准备

### 测试要求

1. **单元测试**: 新代码必须有对应的单元测试
2. **测试覆盖率**: 保持80%以上的测试覆盖率
3. **基准测试**: 性能相关的代码需要基准测试
4. **集成测试**: 复杂功能需要集成测试

## 📝 Pull Request流程

### 提交前检查

1. **代码质量**
   ```bash
   go fmt ./...
   go vet ./...
   golint ./...
   ```

2. **运行测试**
   ```bash
   go test -v .
   go test -v ./startup
   go test -bench=. -v .
   ```

3. **构建检查**
   ```bash
   go build .
   go build ./startup
   ```

### PR模板

```markdown
## 变更类型
- [ ] Bug修复
- [ ] 新功能
- [ ] 文档更新
- [ ] 性能优化
- [ ] 重构

## 变更描述
简要描述此PR的变更内容

## 测试
- [ ] 添加了新的测试用例
- [ ] 所有测试通过
- [ ] 手动测试通过

## 文档
- [ ] 更新了相关文档
- [ ] 添加了代码注释
- [ ] 更新了示例

## 检查清单
- [ ] 代码遵循项目规范
- [ ] 提交信息清晰明确
- [ ] 没有引入破坏性变更
- [ ] 向后兼容
```

### 审查流程

1. **自动检查**: CI/CD自动运行测试和检查
2. **代码审查**: 维护者进行代码审查
3. **讨论修改**: 根据反馈进行修改
4. **合并**: 审查通过后合并到主分支
